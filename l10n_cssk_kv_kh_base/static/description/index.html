CZ/SK Control Statement — Shared Framework

Abstract engine behind the Slovak KV DPH and Czech KH DPH VAT control statements — versioned templates, row mixins and an XSD-validated XML export pipeline

The country-neutral engine behind the Slovak Kontrolný výkaz DPH (KV DPH) and Czech Kontrolní hlášení (KH DPH). Country modules (l10n_sk_kv_dph / l10n_cz_kh_dph) plug in their concrete section sets, thresholds and XML schemas.

It deliberately depends on Odoo core only (account, mail, l10n_cssk_core) — no account.report / account_reports — so the statement and its XML export are Community- and Enterprise-clean, on Odoo 18.0 and 19.0.

Key features

  • cssk.control.statement.version — versioned template + section registry + submission types + threshold. Legislative changes ship as new version records, not new modules.
  • cssk.control.statement — the statement aggregate (mail.thread; draft → preview → exported → submitted), with action_compute_lines and action_export_xml (QWeb render + lxml XSD validation).
  • Three row mixins — detail / summary / reconciliation — for concrete section models to inherit.
  • account.move.line — stored cssk_control_section_code (computed via a country-overridable resolver, reverse-charge first) + a multi-VAT override.
  • account.tax — cssk_control_section_default + cssk_control_is_reverse_charge; account.journal — default-section override.

Usage

Accounting ▸ Reporting ▸ VAT Control Statement. Use New Control Statement to create one for a period, Compute to populate the sections from the period's postings, review the per-section detail, then Export XML. The concrete section set, thresholds and schema come from the installed country module; statement versions live under the localization root menu.

Wizards

Create VAT Control Statement (Accounting ▸ Reporting ▸ VAT Control Statement ▸ New Control Statement)

What it does: creates a control statement for a period and computes it in one step.

How to use: pick the company, the statement version (filtered to the company's fiscal country), the submission type, the period type (monthly / quarterly) and the period (date from / date to), then Create; the wizard builds the cssk.control.statement, runs the computation and opens the new statement.
