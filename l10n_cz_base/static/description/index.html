Czech IBAN & legacy account number conversion and variable / constant / specific symbols

This module provides the Czech-specific building blocks shared by other modules (for example ISDOC e-invoicing). It is kept deliberately lightweight and depends only on the account module. It adds bidirectional conversion between a Czech IBAN and the legacy domestic "prefix-number/bankcode" account number on res.partner.bank, together with the Variable, Constant and Specific symbol fields (VS / KS / SS) on account.move.

Key features

  • On res.partner.bank, the legacy account number, account prefix (předčíslí) and four-digit bank code are stored fields computed from the IBAN, which stays the primary storage format. The IBAN is split following the CNB layout, and leading zeros are stripped from the legacy representation.
  • Helper methods build a valid Czech IBAN (ISO 13616 mod-97 check digits) from legacy parts and convert a legacy "prefix-number/bankcode" string to an IBAN, so input from external documents can be normalised to IBAN.
  • On account.move, Variable symbol (VS), Constant symbol (KS) and Specific symbol (SS) fields. The Variable symbol is computed (digits only) from the invoice number for customer documents and from the reference for vendor documents, and remains editable.

Usage

Open a partner's bank account (res.partner.bank) and enter the IBAN in the account number field; the bank code and legacy account number parts are filled automatically from it. On an invoice or journal entry (account.move) the Variable symbol is proposed automatically from the document number (or vendor reference) and can be overridden, while the Constant and Specific symbols can be filled as needed.
